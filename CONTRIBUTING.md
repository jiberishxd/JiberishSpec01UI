# Contributing

Thanks for helping. Bug reports, ideas and pull requests are all welcome.

## Reporting a bug

Open an issue with the **Bug report** form. The most useful things to include:

- the client (Retail or Forever) and the addon version (shown on the hub's About page),
- the full error text from BugSack/BugGrabber, or `/console scriptErrors 1`,
- what you did just before it happened, and a screenshot if it's visual,
- your profile string (Profiles page → Export) if the problem depends on your settings.

## Suggesting a feature

Open an issue with the **Feature request** form. Describe what you want to do in game rather
than how to build it; a screenshot or mock-up helps for anything visual.

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Run `make hooks` once, so staged Lua files are checked on every commit.
3. Make your change. Keep to the SPEC-01 look: build interface parts from the kit in
   `JiberishSpec01UI/Kit/` (shells, keys, lamps, LCDs, controls, motion and sounds) rather than
   new one-off art, keep edges on whole physical pixels (`UI.Pixel`), and respect the Reduce
   motion and sound settings.
4. Run `make check`. It must pass with no new warnings.
5. Add a line to `CHANGELOG.md` under the next version, in plain language for players.
6. Open the pull request with what changed, why, and how you tested it in game (which client).

### Code rules

These keep the addon working with WoW 12.x's protected and secret values; pull requests that
break them can't be merged:

- Never compare, test or do arithmetic on a value that may be secret. Check it with
  `UI.Util.IsSecret` first, and pass secret values only to setters (`SetText`,
  `SetFormattedText`, `SetValue`, `SetTimerDuration`, `SetAlphaFromBoolean`).
- Touch Blizzard code only through post-hooks (`hooksecurefunc`, `HookScript`). Keep the
  addon's data in its own tables, never as fields on Blizzard frames.
- Never move, show, hide or reparent protected frames in combat; queue it with
  `UI:AfterCombat`. Never reparent Edit Mode system frames.
- Don't call `ReloadUI`; use a dialog or toast action with `reload = true`, or `Kit:ReloadKey`.
- Don't register `COMBAT_LOG_EVENT_UNFILTERED`.
- Keep every file's main chunk well under 200 locals (`make check` warns at 160). Group
  sections in `do ... end` blocks, or split the file.
- New settings get a default inside the module's `-- defaults:begin` / `-- defaults:end` block
  and a hub row with `since = '<next version>'`.

### Media

Art and sounds are generated by the scripts in `tools/`; don't hand-edit the `.tga` or `.mp3`
files. Re-run the script, and update `tests/fixtures/hardware-media.json` through it.
